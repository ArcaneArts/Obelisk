# S3 adapter

Uses object_store 0.12.5 with `aws`, without its filesystem/default features.
Source evaluation: `src/aws/mod.rs::put_opts` maps `PutMode::Create` to
`If-None-Match: *` and `PutMode::Update` to `If-Match` using the GET ETag.
The adapter forces `S3ConditionalPut::ETagMatch`, requires response ETags, and
never falls back to unconditional writes. The engine must resolve request records
after conflicts because a transport retry may conceal a successful earlier PUT.

Credentials come from object_store's configured provider (environment, workload
identity, instance/container credentials, or a caller-supplied builder). No secrets
are stored in the database configuration. Use a dedicated bucket/prefix and IAM
permissions scoped to it. Object listings are maintenance operations only.

Opt-in actual AWS S3 storage contract:

```sh
OBELISK_S3_BUCKET=your-test-bucket \
OBELISK_S3_TEST_PREFIX=obelisk-tests \
cargo test -p obelisk-storage --features s3 --test s3_real -- --ignored --nocapture
```

The test creates a UUID subprefix, deletes only its disposable contract-test object,
and retains its HEAD for inspection. Database historical objects are never cleaned
up automatically. Custom endpoints must be labeled as emulator validation separately.
No real S3 tests have run unless recorded in IMPLEMENTATION.md.


## Multiprocess recovery and measurements

The same process harness used for folders can run against actual AWS S3:

```sh
OBELISK_S3_BUCKET=your-test-bucket \
OBELISK_S3_TEST_PREFIX=obelisk-tests \
cargo test -p obelisk --features s3 --test multiprocess \
  real_s3_multiprocess_and_crash_recovery -- --ignored --nocapture
```

It synchronizes independent processes for initialization races, disjoint atomic
batches, identical request IDs and contended revision updates. Writers are killed
at snapshot, segment, receipt, page, root, publication, and acknowledgement
boundaries. Fault stages classify object envelope kinds, independent of the
number of prepared objects. Each scenario has a fresh UUID prefix, and all database
objects are retained for inspection. There is no automatic remote cleanup.

The baseline workload can also target a fresh S3 prefix:

```sh
OBELISK_BASELINE_BACKEND=s3 \
OBELISK_S3_BUCKET=your-test-bucket \
OBELISK_S3_TEST_PREFIX=obelisk-tests \
cargo run --release -p obelisk --features s3 --example baseline
```

Counters measure logical adapter operations and transferred bytes, not physical
HTTP requests or retries inside object_store. Capture service-side metrics when
measuring actual S3 request cost. Record real-service evidence before treating the
S3 acceptance criteria as satisfied.
