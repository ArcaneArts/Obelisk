# S3 adapter

Uses object_store 0.12.5 with `aws`, without its filesystem/default features.
Source evaluation: `src/aws/mod.rs::put_opts` maps `PutMode::Create` to
`If-None-Match: *` and `PutMode::Update` to `If-Match` using the GET ETag.
The adapter forces `S3ConditionalPut::ETagMatch`, requires response ETags, and
never falls back to unconditional writes. The engine must resolve request records
after conflicts because a transport retry may conceal a successful earlier PUT.

Credentials come from object_store's configured provider (environment, workload
identity, instance/container credentials, or a caller-supplied builder). No secrets
are stored in the database configuration. Use a dedicated bucket/prefix and IAM
permissions scoped to it. Object listings are maintenance operations only.

Opt-in actual AWS S3 storage contract:

```sh
OBELISK_S3_BUCKET=your-test-bucket \
OBELISK_S3_TEST_PREFIX=obelisk-tests \
cargo test -p obelisk-storage --features s3 --test s3_real -- --ignored --nocapture
```

The test creates a UUID subprefix, deletes only its disposable contract-test object,
and retains its HEAD for inspection. Database historical objects are never cleaned
up automatically. Custom endpoints must be labeled as emulator validation separately.
No real S3 tests have run unless recorded in IMPLEMENTATION.md.


## Multiprocess recovery and measurements

The same process harness used for folders can run against actual AWS S3:

```sh
OBELISK_S3_BUCKET=your-test-bucket \
OBELISK_S3_TEST_PREFIX=obelisk-tests \
cargo test -p obelisk --features s3 --test multiprocess \
  real_s3_multiprocess_and_crash_recovery -- --ignored --nocapture
```

It synchronizes independent processes for initialization races, disjoint atomic
batches, identical request IDs and contended revision updates. Writers are killed
at snapshot, segment, receipt, page, root, publication, and acknowledgement
boundaries. Fault stages classify object envelope kinds, independent of the
number of prepared objects. Each scenario has a fresh UUID prefix, and all database
objects are retained for inspection. There is no automatic remote cleanup.

The baseline workload can also target a fresh S3 prefix:

```sh
OBELISK_BASELINE_BACKEND=s3 \
OBELISK_S3_BUCKET=your-test-bucket \
OBELISK_S3_TEST_PREFIX=obelisk-tests \
cargo run --release -p obelisk --features s3 --example baseline
```

Counters measure logical adapter operations and transferred bytes, not physical
HTTP requests or retries inside object_store. Capture service-side metrics when
measuring actual S3 request cost. Record real-service evidence before treating the
S3 acceptance criteria as satisfied.

## Query-foundations qualification

The multiprocess command above now exercises hierarchy queries during independent
writers, pinned pagination across parent deletion/recreation, and typed page-family
kill points, including split-producing 256-document batches. It still requires an
externally configured dedicated AWS bucket/prefix. No actual-AWS execution is
claimed by successful folder or memory-adapter runs.

Run the same bounded scaling workload with an S3-only build when configured:

```sh
OBELISK_BASELINE_BACKEND=s3 \
OBELISK_S3_BUCKET=your-test-bucket \
OBELISK_S3_TEST_PREFIX=obelisk-tests \
cargo run --release -p obelisk --no-default-features --features s3 \
  --example scaling --locked
```

Defaults are 100,000 documents and 10,000 successive requests on one document.
`OBELISK_SCALING_MAX` and `OBELISK_SCALING_REQUESTS` may lower the work budget for
smoke tests. Each invocation uses a fresh UUID subprefix and retains remote data.
Capture region, configuration, tested revision, actual results, and service-side
HTTP/retry metrics; logical counters cannot establish physical request costs.
No dedicated bucket/test prefix was supplied for this Task, so the actual AWS
contract, expanded recovery/query suite, and scaling qualification remain open.

## Explicit emulator qualification

Custom endpoints have separate ignored tests; the actual-AWS entry points still
reject endpoint overrides. Provision a dedicated emulator bucket and supply its
credentials externally. Set `AWS_ENDPOINT` explicitly; for a local HTTP endpoint
also set `AWS_ALLOW_HTTP=true`. Never use production credentials for a local
emulator. With `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
`OBELISK_S3_BUCKET` and `OBELISK_S3_TEST_PREFIX` configured:

```sh
cargo test -p obelisk-storage --no-default-features --features s3 \
  --test s3_real emulator_s3_contract --locked -- --ignored --nocapture
cargo test -p obelisk --no-default-features --features s3 \
  --test multiprocess emulator_s3_multiprocess_and_crash_recovery \
  --locked -- --ignored --nocapture
OBELISK_BASELINE_BACKEND=s3 OBELISK_SCALING_MAX=1000 \
  OBELISK_SCALING_REQUESTS=100 \
  cargo run --release -p obelisk --no-default-features --features s3 \
  --example scaling --locked
```

These reuse the storage contract and complete process/query crash harness through
S3 HTTP transport. Each test creates UUID subprefixes and retains database objects;
the contract deletes only its disposable byte-test object. The shortened scaling
command is an emulator smoke workload, not the full 100,000-document qualification.
Record the server version/image, host, tested revision, exact workload and results.
Emulator success does not satisfy the actual-AWS gate or establish hardware
power-loss durability. No server setup or remote cleanup is performed by tests.
